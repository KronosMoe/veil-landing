# Domain docs

This repository uses a single-context domain-document layout.

Before exploring domain behavior, read root `CONTEXT.md` when it exists and any relevant ADRs under `docs/adr/`. Missing domain docs are expected; proceed silently and let domain-modeling create them when terminology or decisions are resolved.

Use vocabulary defined in `CONTEXT.md` in issue titles, hypotheses, tests, and proposals. Explicitly flag any recommendation that conflicts with an existing ADR.
